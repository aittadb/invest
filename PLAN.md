# Investor App Implementation Plan

This file is the flat graph of accepted, unfinished implementation work. Stable `TASK-NNN` identifiers must not be renumbered or reused. List order is a topological reading aid, not a serial execution order.

Each task should be the smallest coherent increment that can finish in one focused commit with an objective pass/fail definition of done. `Depends on` names only direct prerequisites. A dependency recorded in `CHANGELOG.md` is satisfied; one still present here is not. A task whose dependencies are satisfied and which has no external blocker may proceed in parallel with every other ready task, preferably in an isolated Git worktree. Do not combine independent routes, storage contracts, security controls, UI flows, migrations, or live proof matrices. Completed tasks move to `CHANGELOG.md` with evidence and are removed from this file.

- [ ] TASK-045: Define mutation-capable hypermedia action contracts. Depends on: `TASK-022`. DoD: framework-independent action contracts support the required safe and mutating methods, request media types, bounded typed fields, and currently allowed transitions; shared tests prove HTML form and JSON action parity without coupling actions to a specific route implementation.
- [ ] TASK-046: Define the browser mutation security boundary. Depends on: `TASK-004`, `TASK-028`. DoD: a reusable request guard authenticates the trusted actor and enforces allowed origin, CSRF proof, bounded body input, and non-disclosing failure mapping before mutation code runs; focused tests cover missing, malformed, spoofed, expired, cross-origin, and valid requests without embedding feature policy in the guard.
- [ ] TASK-030: Prove the configured AittaDB OAuth client path. Depends on: none. Blocked by: the selected AittaDB deployment exposing and configuring the required OAuth client path. DoD: the selected AittaDB deployment advertises Authorization Code with PKCE, a confidential Investor App client has only the required storage scopes and exact redirect URIs, secrets remain hosted-only, and a development callback obtains and validates a scoped token without logging credentials.
- [ ] TASK-008: Define investment indication contracts. Depends on: `TASK-006`, `TASK-040`. DoD: personal indication, company indication, lifecycle state, company identifier normalization, acknowledgment requirement, participant-visible transitions, owner rejection, and history-entry contracts are typed and documented; tests cover one personal active indication, company duplicate non-disclosure, withdrawal/reactivation, and material-acknowledgment blocking.
- [ ] TASK-010: Define aggregate and reconciliation contracts. Depends on: `TASK-008`, `TASK-040`. DoD: aggregate summary, contributing-state rules, stored-versus-calculated reconciliation preview, correction confirmation, and public sanitization contracts are typed and documented; tests cover active-only contribution, rejected/withdrawn exclusion, oversubscription display data, and no identity/note exposure.

DoD: deterministic in-memory campaign/setup/phase repository passes the campaign contract tests, rejects campaign-specific defaults, preserves setup history, and documents that it is not production storage.
- [ ] TASK-014: Implement the in-memory content and acknowledgment repositories. Depends on: `TASK-006`, `TASK-012`.
