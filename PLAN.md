# Investor App Implementation Plan

This file is the flat graph of accepted, unfinished implementation work. Stable `TASK-NNN` identifiers must not be renumbered or reused. List order is a topological reading aid, not a serial execution order.

Each task should be the smallest coherent increment that can finish in one focused commit with an objective pass/fail definition of done. `Depends on` names only direct prerequisites. A dependency recorded in `CHANGELOG.md` is satisfied; one still present here is not. A task whose dependencies are satisfied and which has no external blocker may proceed in parallel with every other ready task, preferably in an isolated Git worktree. Do not combine independent routes, storage contracts, security controls, UI flows, migrations, or live proof matrices. Completed tasks move to `CHANGELOG.md` with evidence and are removed from this file.

- [ ] TASK-048: Parse opt-in hosted AittaDB OAuth configuration. Depends on: `TASK-046`. DoD: one strict deployment-boundary parser accepts only a complete exact HTTPS issuer, callback URL under the configured app origin and owner route, confidential client identifier and hosted secret, least-privilege storage scopes, and cryptographic key material; absent configuration keeps the capability disabled, partial or malformed configuration fails closed without exposing values, and focused parser tests plus lint, typecheck, and build pass.

- [ ] TASK-049: Persist OAuth proof transactions and closed evidence in D1. Depends on: `TASK-045`. DoD: a checked-in migration and one bounded adapter provide atomic single-use transaction claims plus closed verified-proof metadata without persisting authorization codes, tokens, client secrets, PKCE verifiers, raw state, cookie plaintext, or owner identifiers; replay, expiry, write failure, and migration packaging are tested, and lint, typecheck, and build pass.

- [ ] TASK-050: Add an encrypted owner OAuth CSRF session. Depends on: `TASK-045`, `TASK-047`. DoD: the owner connection resource can issue and verify a short-lived host-only `Secure`, `HttpOnly`, `SameSite=Lax` CSRF cookie bound to the trusted owner and exact app origin; form and JSON mutation discovery remain equivalent, tampering, expiry, actor mismatch, origin mismatch, and missing key material fail closed, and focused tests plus lint, typecheck, and build pass.

- [ ] TASK-051: Compose the hosted owner OAuth proof capability. Depends on: `TASK-048`, `TASK-049`, `TASK-050`. DoD: the production Worker injects the owner connection route only when complete OAuth configuration, D1, and cryptographic capabilities are present; initiation and callback use the exact configured issuer, redirect URI, scopes, durable single-use claim, and closed proof sink; incomplete deployments keep the route absent, no credential enters logs or responses, and focused composition tests plus full validation pass.

- [ ] TASK-030: Prove the configured AittaDB OAuth client path. Depends on: `TASK-051`. Blocked by: an active acceptance operator must provision the confidential client and complete the acceptance sign-in once the hosted callback is deployed. DoD: the selected AittaDB deployment advertises Authorization Code with PKCE, a confidential Investor App client has only the required storage scopes and exact redirect URIs, secrets remain hosted-only, and a development callback obtains and validates a scoped token without logging credentials.
