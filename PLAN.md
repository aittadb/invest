# Investor App Implementation Plan

This file is the flat queue of accepted, unfinished implementation work. Stable `TASK-NNN` identifiers must not be renumbered or reused.

Each task should be the smallest coherent increment that can finish in one focused commit with an objective pass/fail definition of done. Do not combine independent routes, storage contracts, security controls, UI flows, migrations, or live proof matrices. Completed tasks move to `CHANGELOG.md` with evidence and are removed from this file.

- [ ] TASK-006: Define package content and acknowledgment contracts. DoD: package section, ordering, immutable version, content hash, material-change, acknowledgment text, and acceptance-record contracts are typed and documented; tests cover empty-section hiding, immutable snapshot creation, renewed-acceptance requirements, and unsafe Markdown rejection at the contract boundary.
- [ ] TASK-007: Define participant profile and consent contracts. DoD: access-registration profile, declared interest, account email label, marketing consent, account-deletion request state, and editable-field rules are typed and documented; tests cover first-registration requirements, profile updates, consent withdrawal, and deletion-withdraws-active-interest intent.
- [ ] TASK-008: Define investment indication contracts. DoD: personal indication, company indication, lifecycle state, company identifier normalization, acknowledgment requirement, participant-visible transitions, owner rejection, and history-entry contracts are typed and documented; tests cover one personal active indication, company duplicate non-disclosure, withdrawal/reactivation, and material-acknowledgment blocking.
- [ ] TASK-009: Define founder application contracts. DoD: founder application fields, contribution-area choices, lifecycle state, separate-from-investment rule, and history-entry contracts are typed and documented; tests cover create/edit/withdraw behavior and the ability to have founder and investor records independently.
- [ ] TASK-010: Define aggregate and reconciliation contracts. DoD: aggregate summary, contributing-state rules, stored-versus-calculated reconciliation preview, correction confirmation, and public sanitization contracts are typed and documented; tests cover active-only contribution, rejected/withdrawn exclusion, oversubscription display data, and no identity/note exposure.
- [ ] TASK-011: Define audit and manual-notification contracts. DoD: audit event shape, actor attribution policy, notification-template, copied-versus-sent distinction, export event, and redaction rules are typed and documented; tests cover audit append intent, manual sent-marker behavior, and no credential or private-note fields in public errors.
- [ ] TASK-012: Define the `StorageAdapter` contract suite. DoD: adapter interface, transaction/idempotency expectations, pagination boundary, compare-and-set requirement, non-disclosing failure shape, and shared contract-test harness are documented and typed; tests run against a minimal fake adapter proving the harness detects authorization, duplicate, drift, and disclosure failures.
- [ ] TASK-013: Implement the in-memory campaign repository. DoD: deterministic in-memory campaign/setup/phase repository passes the campaign contract tests, rejects campaign-specific defaults, preserves setup history, and documents that it is not production storage.
- [ ] TASK-014: Implement the in-memory content and acknowledgment repositories. - [ ] TASK-015: Implement the in-memory participant repository. DoD: deterministic in-memory personal/company indication repository passes indication contract tests, enforces one personal active indication, enforces company uniqueness without disclosure, records immutable history, and exposes idempotent withdrawal/reactivation/rejection transitions.

- [ ] TASK-018: Implement the in-memory founder application repository. DoD: deterministic in-memory founder application repository passes founder contract tests, keeps founder records separate from investment indications, records immutable history, and supports edit and withdrawal by owner subject only.
- [ ] TASK-019: Implement the in-memory audit and notification repositories.
